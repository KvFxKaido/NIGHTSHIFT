# Live Cred (superseded)

Status: **Retired 2026-09-12. Never implemented.** Superseded by finite Surge
tanks: a small number per car, capacity bought in the garage, full at the start
of every event, no mid-race refill and no passive recharge. Style is reputation
only and buys nothing.

Cred existed to stop nitrous becoming a crutch. It answered that with three
currencies, chain rules, a guard against Surge feeding the style that fuels it,
and a settlement path that replays must never re-run -- a large machine for one
question that scarcity answers on its own. The tank model also dissolves the
hoarding risk this document worries about below: you buy the bottle rather than
the fill, so spending a tank costs nothing and a restart cannot farm them.

This is kept, not deleted, because the reasoning is worth reading before anyone
proposes it again, and because the style sources and chain rules below remain a
good list if style ever needs to feed something. Everything below this line is
the retired design, unchanged.

Live Cred is NIGHTSHIFT's style-to-speed economy. Skilled and expressive
driving generates a temporary race currency. The player can burn that currency
on nitrous during the race or carry it across the finish line to buy parts.

The intended decision is simple:

> Spend Cred to improve the result now, or preserve it for the car you are
> building next.

This system takes the expressive scoring appeal of a Kudos-style system and
makes it tactically relevant during the race. It should reward fast, deliberate
driving rather than tricks performed separately from racing.

## Design goals

- Make style affect race outcomes instead of existing only as a post-race score.
- Create understandable tension between winning now and progressing sooner.
- Reward mastery of the car, rivals, and city through one connected system.
- Give nitrous a player-authored supply rather than a passive recharge timer.
- Preserve a restrained race HUD and a deterministic, replayable simulation.

## Resource model

The system uses three race-facing values and one permanent record.

### Chain Cred

Provisional value generated by the current style chain. A collision or invalid
driving state can destroy it before it is secured.

### Live Cred

Cred secured during the current race. It can be spent on nitrous but cannot be
used for garage purchases until the event finishes.

### Banked Cred

Permanent garage currency. Race-time nitrous can never consume it. Performance
parts use Banked Cred in the first vertical slice.

### Lifetime Style

A non-spendable record of gross style earned. Spending Live Cred does not erase
accomplishments, reputation, unlock progress, or leaderboard style totals.

## Race loop

1. Valid style actions add Chain Cred and extend the multiplier.
2. Completing a clean sequence converts Chain Cred into Live Cred.
3. A collision loses the current unbanked chain, not secured Live Cred.
4. Holding Surge burns Live Cred to provide nitrous acceleration.
5. Finishing commits remaining Live Cred and the event payout to Banked Cred.
6. Restarting or abandoning the event commits nothing from that attempt.

The economy settlement is:

```text
new banked cred = previous banked cred
                  + remaining live cred
                  + position payout
                  + event bonuses
```

Only an authoritative live race may settle the economy. Replays reproduce the
run but cannot award Cred a second time.

## Style sources

Style sources must represent useful or risky racing behavior:

- Sustained slipstream
- Clean apex sequences
- Controlled slides with meaningful speed and forward progress
- Close barrier or traffic proximity
- Clean jumps and landings
- Overtakes
- Discovering or executing shortcuts
- Completing authored Nightlines

Nightlines are high-value environmental sequences such as the three Freight S
apexes. They bank a chain immediately on a clean exit and connect the style
system directly to learning the district.

## Chain rules

- Braking does not break a chain. Correct braking must remain valid racing.
- Repeating one action produces diminishing returns.
- Drifts require minimum speed, forward course progress, and a useful slip-angle
  range. Donuts and stationary steering score nothing.
- Contact ends the current chain; severe contact discards its Chain Cred.
- A short clean recovery window banks ordinary chains automatically.
- Nightline exits and clean overtakes may bank immediately.
- Style earned while Surge is active is suppressed, preventing a self-feeding
  boost loop.

Exact thresholds, multipliers, and bank timing are tuning values, not design
law. The scoring events and currency state belong to the deterministic
simulation; the renderer only presents them.

## Surge

Surge is the working name for player-controlled nitrous.

- Input target: keyboard Shift and standard-gamepad Circle/B.
- Surge consumes Live Cred at a clearly displayed rate.
- It improves acceleration and temporarily extends useful top speed.
- It cannot draw from Banked Cred.
- Releasing the input stops the drain immediately.
- The starter car has a baseline Surge system so the core hook exists from the
  first race. Later upgrades change efficiency, delivery, and capacity rather
  than unlocking the verb from nothing.

The first implementation should use a linear drain. Tiered power and variable
burn rates add tuning complexity before the fundamental decision is proven.

## Economy position

For the first vertical slice, Cred should be the only currency used to purchase
performance parts. Reputation remains the chapter-unlock system. A separate
cash currency should not be introduced unless it gains a distinct purpose;
duplicating Cred with ordinary money would weaken the hook and complicate every
reward screen.

Base event payouts must guarantee forward progress even for weaker players.
Style increases purchasing speed but cannot be the only path to essential
upgrades. There are no repair bills or other loss spirals in the first slice.

Position payout differences should usually make a short, decisive Surge worth
using, but not always. If spending Cred is mathematically correct every time,
there is no decision. If hoarding is always correct, the game's most distinctive
button becomes a trap.

## Example decision

Illustrative values only:

- Banked Cred before the race: 1,800
- Tracked turbo kit: 2,200
- Current Live Cred: 300
- Second-place payout: 150
- First-place payout: 250
- Expected Surge cost to attempt the pass: 220

Taking second produces 2,250 total Cred and buys the turbo immediately. Burning
220 Cred and winning produces 2,130, delaying the purchase. The faster finish
is not automatically the better career decision.

The game should expose that tradeoff without requiring a spreadsheet.

## Race HUD

The compact HUD needs to communicate:

- Current chain value and multiplier
- Secured Live Cred
- Surge drain while active
- Projected post-race Banked Cred
- Optional tracked-part price

Example:

```text
CHAIN      +180 x2.4
LIVE CRED   620
SURGE       -40/s
TURBO     2,420 / 2,500 projected
```

The tracked-part line is optional and player-selected. It provides the emotional
context for the decision without turning the normal HUD into an accounting
screen.

## First prototype

The smallest useful proof includes:

1. Controlled slides and close barrier driving as style sources.
2. One chain multiplier and a clear collision break.
3. Live Cred banking after a clean recovery window.
4. Shift/Circle Surge with a linear Cred drain.
5. A fictional tracked part and projected balance on the HUD.
6. No persistence or real garage transaction yet.

Nightlines, drafting, overtakes, and full race settlement should follow only if
the basic earn-versus-burn decision is already enjoyable.

## Acceptance criteria

- Players understand that only current-race Cred is at risk.
- Players sometimes use Surge and sometimes deliberately preserve Cred.
- A visible part target changes at least one race decision.
- Fast, clean racing earns more than low-speed style farming.
- Collisions threaten the current chain without erasing previous progress.
- Boost cannot generate enough Cred to sustain itself.
- Restart and replay cannot duplicate Banked Cred.
- The decision remains readable at racing speed.

## Open tuning questions

- Final player-facing names for Cred, Chain, and Surge
- Chain bank delay and multiplier ceiling
- Surge drain rate and acceleration profile
- Position payout curve
- Whether minor contact reduces or entirely breaks a chain
- How much rival drafting contributes relative to solo techniques
- Whether special events can prohibit Surge or reward finishing with unused Cred
